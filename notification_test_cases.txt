====================================================================
          NOTIFICATION MODULE - COMPREHENSIVE TEST CASES
====================================================================

This document outlines the test cases for the Notification Module 
in the Admin Panel, covering all combinations of Types, Target 
Audiences, and Content Links.

--------------------------------------------------------------------
TEST CATEGORY 1: TARGET AUDIENCE SELECTION
--------------------------------------------------------------------

Test Case 1.1: Send to "All Users"
- Options: Send To = "All Users"
- Expected Behavior: The notification is sent to every user in the database. 
  Backend successfully registers it, and the total 'sent' count matches total users.

Test Case 1.2: Send to "Subscribers Only"
- Options: Send To = "Subscribers Only"
- Expected Behavior: The notification is only sent to users with an active 
  subscription. Non-subscribed users should not receive it.

Test Case 1.3: Send to "Specific User" (Valid User)
- Options: Send To = "Specific User", User Search = Select a user from dropdown
- Expected Behavior: Notification is sent ONLY to the selected user. The recent 
  notifications table should display the user's name/email in the "Target" column.

Test Case 1.4: Send to "Specific User" (No User Selected)
- Options: Send To = "Specific User", User Search = Left Blank
- Expected Behavior: An error toast should appear saying "Please select a specific user" 
  and the form should not submit.

--------------------------------------------------------------------
TEST CATEGORY 2: LINK TO CONTENT OPTIONS
--------------------------------------------------------------------

Test Case 2.1: Attachment Type = "None"
- Options: Attachment Type = "None"
- Expected Behavior: No Action URL or image is attached to the payload. When 
  viewing the notification details, Action URL should be "—".

Test Case 2.2: Attachment Type = "Content" (Movie Selection)
- Options: Attachment Type = "Content", Link to Content = "Movie", Search Movie = Select a movie
- Expected Behavior: Form submits successfully. Backend fetches the movie, extracts 
  its poster image, and generates a deep link (e.g., mirchiapp://movies/id/<id>). 
  Details modal should display "movie" as Linked Content.

Test Case 2.3: Attachment Type = "Content" (Series Selection)
- Options: Attachment Type = "Content", Link to Content = "Series", Search Series = Select a series
- Expected Behavior: Form submits successfully. Backend fetches the series, extracts 
  its poster/thumbnail image, and generates a deep link (e.g., mirchiapp://series/id/<id>). 
  Details modal should display "series" as Linked Content.

Test Case 2.4: Attachment Type = "Subscription Plan" (Valid Selection)
- Options: Attachment Type = "Subscription Plan", Search Plan = Select a subscription plan
- Expected Behavior: Form submits successfully. Backend fetches the plan, sets 
  no image (or a default), and generates a deep link (e.g., mirchiapp://plans/id/<id>). 
  Details modal should display "plan" as Linked Content.

Test Case 2.5: Attachment Type = (Content/Plan) but No Content Selected
- Options: Attachment Type = "Content" (or Plan), Content Search = Left Blank
- Expected Behavior: An error toast should appear saying "Please select a Movie/Series/Plan" 
  and the form should not submit.

--------------------------------------------------------------------
TEST CATEGORY 3: NOTIFICATION TYPES
--------------------------------------------------------------------

Test Case 3.1: Type = "GENERAL"
- Expected Behavior: Notification is created with GENERAL type. The table and 
  modal display a grey/slate badge for GENERAL.

Test Case 3.2: Type = "SYSTEM"
- Expected Behavior: Notification is created with SYSTEM type. The table and 
  modal display a blue badge for SYSTEM.

Test Case 3.3: Type = "PLAN"
- Expected Behavior: Notification is created with PLAN type. The table and 
  modal display a purple badge for PLAN.

Test Case 3.4: Type = "PROMOTIONAL"
- Expected Behavior: Notification is created with PROMOTIONAL type. The table 
  and modal display an orange/amber badge for PROMOTIONAL.

--------------------------------------------------------------------
TEST CATEGORY 4: UI & VALIDATION
--------------------------------------------------------------------

Test Case 4.1: Empty Title or Message
- Options: Title = "", Message = ""
- Expected Behavior: An error toast should appear saying "Please fill in title 
  and message" and the form should not submit.

Test Case 4.2: Pagination Controls
- Action: Click "Next" and "Prev" on the Recent Notifications table
- Expected Behavior: The table should successfully load 10 notifications per page 
  without full page reloads. The current page number should update correctly.

Test Case 4.3: View Notification Modal
- Action: Click the "Eye" icon on a notification row
- Expected Behavior: Modal opens with correct Type badge, Title, Date, Message, 
  Target User, Action URL, and Linked Content (if applicable). Clicking outside 
  or on the 'X' closes it. Unread notifications become "Read".

Test Case 4.4: Delete Single Notification
- Action: Click the "Trash" icon on a single notification row, accept prompt
- Expected Behavior: Notification is deleted (archived) from the database and 
  disappears from the table.

Test Case 4.5: Delete All Notifications
- Action: Click the "Trash" icon next to the "Refresh" button, accept prompt
- Expected Behavior: All notifications are deleted. Table displays "No notifications 
  sent yet". Pagination resets to Page 1.
